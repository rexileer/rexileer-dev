# Лёгкая аналитика привлечения

Сводка: **Админка → Аналитика привлечения**, `/admin/core/visitlog/`.
Доступ требует права просмотра VisitLog. Владелец выбирает 7/30 дней и рабочие
либо проверочные данные. Не нужно сводить журналы вручную.

## Что означают числа

- Просмотр — успешный GET существующей публичной HTML-страницы RU/EN: главная,
  услуги, каталоги, кейсы, страница описания данных. Обновление даёт ещё просмотр.
  Это не уникальный человек и не сессия. Админка/API/assets/404/HEAD исключены.
- Первые экраны — начало наблюдаемого 30-минутного окна атрибуции: нет валидного
  cookie, изменились корректные UTM либо пришёл внешний referrer. Это приближение,
  не достоверные сессии. Блокировка cookies может делать каждый экран первым.
- Источники — `utm_source`, `utm_medium`, `utm_campaign`, домен внешнего referrer.
  Контактные клики группируются по этим же сохранённым полям. Метки не передаются
  в Telegram и не связываются с фактически полученными сообщениями.
- `telegram_click` / `email_click` — клик по контакту, **не полученная заявка**.
  `case_open` — клик на кейс, а не подтверждённая загрузка. Путь события — страница,
  на которой была ссылка. Просмотры услуг/кейсов считаются сервером отдельно.
- Показываются объёмы выборки, первые 30 строк таблиц, RU/EN отдельными путями.
  До 30 просмотров есть предупреждение о малой выборке. Проценты конверсии,
  уникальные люди и сквозная атрибуция не заявляются.
- Старые записи (`version=0`) не входят в новую сводку: прежняя методика считала
  только `/` с шестичасовым подавлением повторов, а клики не имели источника.
  Их количество за период показывается отдельно без смешивания методик.

## Метки и границы атрибуции

Пример: `/?utm_source=telegram&utm_medium=profile&utm_campaign=oct17_portfolio`.
Разрешены только ASCII-slug с буквы: латиница, цифры, `_`, `-`. Максимальная длина
source/medium/campaign — 64/32/64, регистр приводится к нижнему. Некорректное
значение целиком отбрасывается. Не помещать в метки имена, email, телефоны,
клиентские сведения или другие персональные данные; формат не определяет смысл.
Другие query-параметры не сохраняются в аналитике. Referrer хранится только как
DNS-домен без пути, credentials, query и fragment; собственные домены исключены.

Подписанный `rex_attribution`: фиксированные 30 минут, HttpOnly, SameSite=Lax,
Secure по HTTPS. Постоянного visitor ID нет. В пределах окна сохраняются первый
наблюдаемый экран и источник, пока не обнаружен новый внешний/помеченный заход.
Клик внутри выбранного периода может иметь источник, наблюдавшийся до его начала.
Без cookie атрибуция кликов неполна; пустой источник значит «без метки / неизвестно».
Нет связи между устройствами, Telegram-диалогами, email-доставкой и оплатами.
Без JavaScript остаются SSR, ссылки, просмотры и cookie, но не click events.
Новой формы заявки нет; события успешной заявки не создавались.

## Минимизация и служебный трафик

Новые VisitLog и SiteEvent: только ограниченные пути/метки/домен/время, тип/место
клика, флаг проверки и суточный HMAC IP для ограничения частоты. IP и User-Agent
читаются временно, новые записи сохраняют `ip=NULL`, `user_agent=''`.
IP берётся из REMOTE_ADDR, за приватным nginx — из перезаписываемого им X-Real-IP;
произвольному первому X-Forwarded-For доверия нет. Секрет HMAC/подписи — отдельная
случайная приватная запись AnalyticsKey в существующей БД, не в API/админке;
значения действующих секретов приложения не меняются. Это псевдонимизация,
**не полностью анонимные логи** и не browser fingerprinting.

Старые строки могут содержать исходные IP/UA до истечения срока хранения.
Отдельные access/error-журналы nginx и backups имеют свою политику: очистка
аналитики их не стирает. Фактический сбор описан публично на `/privacy/` и
`/en/privacy/`, ссылка есть в footer. Юридическая оценка не заявляется.

- Известные боты/сканеры, пустой UA, curl/Python, Headless/Playwright,
  авторизованные staff, DNT:1, Sec-GPC:1 исключены.
- `X-Rexileer-Analytics: exclude` исключает собственные технические обращения.
- `X-Rexileer-Analytics: test` создаёт только проверочные строки; подписанный
  cookie переносит этот флаг на последующие страницы/клики. В отчёте они доступны
  только в режиме «Проверочные». Это не секретный bypass авторизации, CSRF или
  лимитов. Для проверки использовать отдельный браузерный контекст и закрыть его.
- Если владелец смотрит сайт без staff-входа/исключающего заголовка и без сигналов
  приватности, такой просмотр может попасть в рабочую выборку.

## Лимиты, устойчивость и хранение

До 60 просмотров и 30 событий в минуту на суточный HMAC IP, отдельно live/test.
Одинаковый клик (тип/место/страница/ключ) за 2 секунды подавляется. Это счётчик
событий, не уникальных пользователей. NAT разделяет лимит; параллельные запросы
могут слегка его превысить. Ограничение основано на индексированных запросах
существующей SQLite, сохраняется при перезапуске worker. Это не защита от всех ботов.

`/api/events/` требует POST/CSRF, ограниченный размер, имя/место/язык/реальный
публичный путь. Произвольные URL/параметры не принимаются. Отбрасываемые события
возвращают204, чтобы не влиять на действие пользователя. Ошибки записи не меняют
публичный HTML; исключение beacon/fetch не отменяет ссылку. В operational warnings
нет содержимого запроса. Нет внешнего трекера, записи экрана или новых контейнеров.

`python manage.py prune_analytics` удаляет только VisitLog/SiteEvent старше90дней,
пакетами по500. Ничего из Project, drafts, providers, пользователей и ключа не
удаляется. Команда выполняется при старте приложения (сбой не блокирует запуск)
и ежедневно системным timer `rexileer-analytics-prune.timer` около03:20UTC.
Его units лежат в `ops/`, устанавливаются существующим main-only deploy.
Контроль: `systemctl list-timers rexileer-analytics-prune.timer`,
`journalctl -u rexileer-analytics-prune.service`. Ручной запуск:
`docker compose exec -T app python manage.py prune_analytics`.

Перед миграциями создаётся приватная резервная копия БД вне checkout.
Проверки: адресные Django tests (атрибуция, фильтры, лимиты, отказ записи,
периоды/права отчёта и retention), Ruff/check/migrations/JS; полный набор — CI.
Браузер: контрольный UTM → услуга → контакты/кейс, мобильный отчёт, RU/EN privacy,
меню, no-JS и искусственный отказ beacon. После deploy повторяется настоящий
контрольный путь в test-режиме и проверяются строки/отчёт/таймер на VPS.
